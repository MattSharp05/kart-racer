# Kart Racer

A low-poly 3D arcade kart racer that runs in the browser on desktop (keyboard) and mobile (touch, landscape), in the spirit of Mario Kart but with original characters and naming. MVP: one track, 4 karts, 1 player vs 7 AI, drift mini-turbos and 6 items (mushroom, banana, green/red shell, star, lightning). Static site on Vercel, no backend. Online multiplayer is v2.

## Structure

- `src/sim/` — pure deterministic simulation (60 Hz fixed step, seeded RNG, plain-JSON state). Tunables in `sim/tuning.ts`, data in `sim/data/`.
- `src/render/` Three.js · `src/input/` keyboard/touch → `InputFrame` · `src/ui/` DOM HUD/menus · `src/audio/` Web Audio synth
- **Local multiplayer (MK-144):** up to 4 people on one screen. `src/input/slots.ts` `PlayerSlots` (slot 0 = P1 … 3 = P4) holds one `InputSource` per slot (`src/input/sources/types.ts`: `read()` → `InputFrame`, optional `takePause()`, `autopilot`, `dispose()`); `RaceSession.slots` / `slotKarts` map slot `i` to the race's `i`-th `local` kart (P1 = this device's keyboard/touch). When a race starts, empty slots ask `inputSourceProviders` (`src/input/sources/index.ts`: a new controller kind, e.g. the paired phone, is one file exporting an `InputSourceProvider` + one line there), else get the self-driving "Auto" stand-in. Race setup's Players option (racer select, 1–4 keys) → each player picks a racer; results mark every player (`P1 2nd · P2 5th`); any slot's pause opens the pause menu ("Paused by P2"). Local multiplayer races don't count for records or the leaderboard. Scenarios: `local-2p`, `local-4p`, `local-2p-paused`, `local-2p-results`, `local-setup` (a scenario's `players` + `fakePlayers`); e2e: `__game.setSlotInput(slot, frame)`, `__game.pressPause(slot)`, `getState().slotKarts`.
- `src/game/` loop, app state machine, `window.__game` test API
- `src/mk8/` MK8 Mode (lazy-loaded content pack: screens, HUD, render, audio, MK8 content) · `tools/mk8/` asset pipeline (dev only). **Nintendo assets are never committed (ADR 0009); the site serves them only behind a server-checked password (MK-135):** raw files in gitignored `.mk8-raw/` (Matthew fetches them; agent downloads are blocked), `pnpm mk8:build` → gitignored `.mk8-out/`, served at `/mk8/` by `pnpm dev`; without it MK8 Mode shows "pack not installed". On Vercel, `scripts/fetchMk8Pack.mjs` (in `vercel.json`'s build command) copies the private repo `MattSharp05/kart-racer-mk8-assets` `out/` into `dist/mk8/` only when env `MK8_ASSETS_TOKEN` and `MK8_PASSWORD` are set, and Routing Middleware (`middleware.ts` → `gateMk8` in `api/mk8-login.ts`) answers 401 on every `/mk8/*` file (fonts excepted) without the `mk8_session` cookie from `POST /api/mk8-login` (optional `MK8_COOKIE_SECRET`). `public/mk8/` holds only shippable non-Nintendo files (the OFL font). Tests use synthetic fixtures; real-asset checks are deferred on tickets
- **Adding to MK8 Mode (MK-142)** touches only new files plus at most one list line, like ADR 0007's content: a menu screen is a file in `src/mk8/ui/screens/` exporting `screen` + its id in `order.ts`; a scenario group is a file in `src/scenarios/mk8/` + one line in its `groups.ts` (`mk8Start` opens MK8 Mode, `mk8Course` names a driving scenario's course); a fixture model family is a spec in `tests/e2e/fixtures/mk8-pack/specs/` (then `node tests/e2e/fixtures/mk8-pack/make.ts`; never hand-edit `manifest.json`); a tunable block is a file in `src/sim/tuning/mk8/` + one line in `blocks.ts`. How-tos: each folder's README.
- `src/scenarios/` scenario registry · `dev.html` + `src/dev/` = `/dev` index · `/dev/track-editor.html?course=<id>` (MK-100, `src/dev/trackEditor/`, guide `docs/mk8-track-editor.md`): authors an MK8 course's `route.ts`/`materials.ts` on its collision mesh; `src/sim/routeValidation.ts` checks routes; `pnpm dev` adds `POST /__track-editor/save`
- `src/content/` (v2, ADR 0007) — tracks, racers and items, one folder each. **To add one:** create `src/content/<tracks|racers|items>/<id>/` (folder name = id) with `sim.ts` (pure data/logic, sim lint rules; default-exports a `TrackContent`/`RacerContent`/`ItemContent`) and, for racers and items, `render.ts` (may import three; default-exports a `RacerView`/`ItemView`: model, colours, icon, sound, renderer), then add one line to that kind's list in `index.ts` (and `render.ts`); copy an existing folder as the template. No other shared file changes; ids are plain strings checked at lookup, and `registries.test.ts` fails if a folder isn't listed. **Track looks and hazards (MK-49):** a track's `theme` (sky, fog, light, palette, scenery set, night) and its `def.hazards[]` (`mover` · `rotator` · `periodic` · `zoneEffect`, poses a pure function of tick, kinds in `src/sim/hazards/`, views in `src/render/hazards/`) and surface zones (`ice` · `sand` · `conveyor`, effects in `src/sim/surfaces.ts`); `tracks/hazard-test/` is the worked example. A track folder may also have `scenarios.ts` (default-exports `Scenario[]`; one line in `tracks/scenarios.ts`), a `render.ts` (default-exports a `TrackView` whose `scenery()` replaces the theme's scenery set; one line in `tracks/render.ts`), and a zone hazard can take `warning` (HUD text 3 s before it starts) and `dust` (MK-58); `tracks/dune-canyon/` is the full example. MK-59 added a `mover` with an open path (`activeFraction`: runs now and then, gone in between) drawn as a rolling ball (`rolling`: shadow + rumble), and `TrackView.update(scenery, ticks, camera)` for moving scenery (falling snow); `tracks/frostpeak-pass/` uses both. MK-60 added `vehicle` on a `mover` (a car or truck with headlights), kart headlights on `night` tracks (`render/headlights.ts`) and AI steering round predicted movers (`sim/ai/hazards.ts`); `tracks/neon-harbour/` uses them. MK-61 added a `sway` hazard (a straight deck leaning on a timer that pushes karts sideways; its view draws the deck and, via `HazardView.hidesRoad`, replaces the road under it), `routes` (another way round part of a lap over a `shortcuts` floor: lap progress follows it, `sim/routes.ts`, and AI takes it on a seeded share of laps, `sim/ai/routes.ts`), `respawnPoints` (falls in a stretch put you back at its start) and `surface` on a shortcut (`road`: a paved lower path); `tracks/canopy-rush/` uses them. MK-62 added `piston` on a `periodic` crusher (drawn as a steam piston with a shadow, steam and a lamp that flashes `tuning.hazards.crusherWarningSeconds` before it drops, from the kind's `secondsUntilOn`) and AI crusher timing (`sim/ai/hazards.ts` `crusherSpeedLimit`: the AI slows to arrive as the next crusher opens); `tracks/cog-works/` uses them, plus conveyor belts (`conveyor` zones, one lane each way). MK-61 QA round 2 added `animal` on a `mover` (a boar, tapir, tapir calf or deer, `render/hazards/animal.ts`, 2 draws each) and AI dodging of movers on a route (`sim/ai/hazards.ts` `routeDodgeOffset`); `tracks/canopy-rush/` uses them for animals crossing its trail. Items build on the item framework (MK-52): `uses`, kart `effects` (`sim/items/effects.ts`), general `entities` (`sim/items/entities.ts`: straight/homing/returning/area + collision rules), `aiUse`, and in the view `sounds`, `entityModel`/`effectModel` (`renderer: ItemEntityRenderer`) and HUD `overlays` (a multi-use item's `iconFor(uses)` draws its uses left in the slot instead of a "×n" badge, MK-65: `items/turbo-trio/`); `items/test-kit/` is the worked example (`?scenario=item-framework-test`).
- `src/remote/` (MK-146, ADR 0013) phone controllers: the desktop's pairing (`desktop.ts`: `openAddControllers()`, `remoteInput(slot)`; `hub.ts` seats phones by slot, drops silent ones), the phone side (`controller.ts`) and its page `/remote?room=<code>&slot=<n>` (`remote.html` → `page/main.ts`; the look is `page/view.ts` + `remote.css`, which MK-147 replaces), its 60 Hz input protocol (`protocol.ts`, sequence-numbered) and links (`links.ts`: the online stack's WebRTC + Supabase signaling, or BroadcastChannel with `net=local`). The Add Controllers panel is `src/ui/screens/addControllers.ts` (title button 📱 Controllers, desktop only); until split-screen, the phone in slot 1 drives player 1 (merged in `PlayerInput`); a dropped slot-1 phone pauses the race (`Flow.pauseIfRacing`)
- `src/net/` (v2) transport (WebRTC · loopback · BroadcastChannel), binary protocol, rooms, host/client netcode · `supabase/migrations/` SQL schema
- `api/turn.ts` (MK-75, ADR 0008) — a Vercel Function: `GET /api/turn` returns short-lived Cloudflare TURN `iceServers` (env `CLOUDFLARE_TURN_KEY_ID` / `CLOUDFLARE_TURN_API_TOKEN`, Production only; none → 503). Self-contained (no `src/` imports); tests in `tests/api/` (run by `pnpm test`). The client side is `src/net/iceConfig.ts`: one fetch per WebRTC race, 3 s timeout, public STUN fallback
- `tests/e2e/` Playwright specs · `docs/` TDD, ADRs, CREDITS

## Conventions

- `src/sim/**` must not import `three`, DOM, input/render/ui/audio, nor use `Math.random`/`Date` (lint-enforced). Use `sim/rng.ts`.
- No magic numbers in logic — tunables go in `sim/tuning.ts` or data files.
- Units: metres, seconds, radians; +Y up; heading 0 faces −Z.
- Render/UI/audio only read `SimState` and `SimEvent`s; they never mutate sim state.
- `src/net/**` may import `sim/` types but never `render/`/`ui/`. Online races: the host is authoritative (ADR 0005); clients never decide hits, pickups or finishes.
- Screens live in `src/ui/screens/` with their own CSS; content (tracks, racers, items) registers itself (ADR 0007) — don't add cases to shared switches.
- New dependency or architectural change → `/block-ticket` and record an ADR.

MK-102 loadouts: `KartState.loadout` (`{ racer, body, tires, glider }`) makes a kart's physics come from MK8's stat table (`src/mk8/content/stats.ts`, mapped by `tuning.mk8.statMap`) instead of its racer's stats; parts and wheel anchors in `src/mk8/content/parts/`, the kart built from body + 4 tires + hidden glider in `src/mk8/render/kartAssembly.ts`, last loadout in prefs (`src/mk8/loadoutPrefs.ts`). Scenarios: `mk8-karts-lineup` (fixture parts: `specs/karts.ts`), `mk8-loadout-heavy` / `-light`.

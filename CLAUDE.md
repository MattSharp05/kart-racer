# Kart Racer

A low-poly 3D arcade kart racer that runs in the browser on desktop (keyboard) and mobile (touch, landscape), in the spirit of Mario Kart but with original characters and naming. MVP: one track, 4 karts, 1 player vs 7 AI, drift mini-turbos and 6 items (mushroom, banana, green/red shell, star, lightning). Static site on Vercel, no backend. Online multiplayer is v2.

## Stack

TypeScript (strict) · Vite · Three.js · in-house arcade physics (no physics engine) · plain DOM/CSS UI · Web Audio (synthesized) · pnpm · Vitest · Playwright · ESLint + Prettier · GitHub Actions · Vercel · **v2:** Supabase (Realtime for rooms/signaling, Postgres for leaderboards) + WebRTC data channels for race packets. - `pnpm test:e2e` — Playwright (all projects) · `pnpm test:visual` — screenshot tests (chromium, run in CI's Docker image) · `scripts/update-visual-baselines.sh` — regenerate baselines locally with Docker
- `pnpm test:soak` — opt-in runs, alone, in CI's Playwright image: netcode (MK-73: 10-race browser soak at `net-bad` + 4×-throttled online phone check) and phone perf on all 6 tracks (MK-71, `tests/soak/phoneAllTracks.spec.ts`: 4×-throttled Pixel 7 CPU frame rate at `&quality=low`; `FULL_QUALITY=1` adds full quality). Per-track draw-call/triangle budgets run in CI (`tests/e2e/perfAllTracks.spec.ts`) · `pnpm net:sweep` — netcode tuning sweep (`scripts/netSweep.lab.ts`, minutes of CPU)
- `pnpm ai-pass` — cross-track AI pass (MK-71, `scripts/aiPass.lab.ts`): 6 tracks × 5 seeds of 8 AI at 150cc (all finish, race times within 15 %, nobody stuck > 3 s) + each track's `track_limits` under 85 % of the AI's best lap; ~3 min (`SEEDS=`, `TRACKS=a,b`, `CC=200` for another engine class, MK-96); `aiPass.test.ts` runs one seed per track in `pnpm test`
- `pnpm item-balance` — item balance simulation (MK-72, `scripts/itemBalance.lab.ts`): 50 seeded 8-AI races over every track, prints item use / hit shares / lead changes / finish spread and checks the targets; ~5 min, run alone (`RACES=12` for fewer)
- `pnpm racer-balance` — racer balance pass (MK-88, `scripts/racerBalance.lab.ts`): 100 seeded 8-AI races over every track and class, each racer on the grid equally often, items on and off; prints win % / mean place / podium % per racer and checks the targets (nobody > 20 % wins, everybody ≥ 3 %, mean place within 4.5 ± 1.0). Runs in parallel child processes, ~6 min on 4 cores (`RACES=`, `FIRST=` other seeds, `ITEMS=on|off`, `WORKERS=`, `TUNING='{…}'` to sweep tuning values) · `pnpm test:balance` — its 20-race CI smoke (35 % cap, own CI job)
- `pnpm test:sql` — leaderboard SQL tests on a throwaway Postgres (`PG*` env vars; CI's SQL job) · `pnpm track-limits` — prints the leaderboard's `track_limits` SQL from the track data (MK-48; how to apply it: `supabase/README.md`)
- `pnpm mk8:build` — MK8 asset pipeline (MK-93, `tools/mk8/README.md`): converts raw files you provide in `$MK8_RAW` (default `.mk8-raw/`) to GLB/WebP and (MK-94) `.m4a` audio (sounds in `src/mk8/audio/soundIds.ts`, voices by `voiceEvents.ts`, `ffmpeg-static`) + `manifest.json` in `$MK8_OUT` (default `.mk8-out/`), both gitignored; never downloads, never writes `public/` · `pnpm mk8:check` — manifest hashes + `tools/mk8/budgets.json` + every sound id built (not in CI yet) · `pnpm mk8:dae-info` — skeletons in racer DAEs. UI sprites (MK-95): the same build crops `tools/mk8/spriteSpecs.ts` into `$MK8_OUT/ui/` (typed table `src/mk8/ui/sprites.ts`); `pnpm dev` serves `$MK8_OUT` at `/mk8/` and `/dev/mk8-sprites.html` shows every sprite. Needs Node ≥ 22.18; tests in `tools/**/*.test.ts` run in `pnpm test` on generated fixtures
- `pnpm mk8:spike-report` — MK-92 anti-gravity spike numbers (`scripts/antigravSpike.lab.ts`): material mapping, collision triangle counts and `collision.bin` size, 8-kart ground query cost and a 2-lap anti-gravity drive on the synthetic course (`src/mk8/spike/NOTES.md`); the spike page is `/?spike=antigrav` (`&course=<id>` loads a real course's `collision.bin` from `pnpm mk8:build` under `pnpm dev`)
- `pnpm check` — everything CI runs (lint, typecheck, unit, build, e2e)

## Structure

- `src/sim/` — pure deterministic simulation (60 Hz fixed step, seeded RNG, plain-JSON state). Tunables in `sim/tuning.ts`, data in `sim/data/`.
- `src/render/` Three.js · `src/input/` keyboard/touch → `InputFrame` · `src/ui/` DOM HUD/menus · `src/audio/` Web Audio synth
- `src/game/` loop, app state machine, `window.__game` test API
- `src/mk8/` MK8 Mode (lazy-loaded content pack: screens, HUD, render, audio, MK8 content) · `tools/mk8/` asset pipeline (dev only). **Nintendo assets are never committed (ADR 0009); the site serves them only behind a server-checked password (MK-135):** raw files in gitignored `.mk8-raw/` (Matthew fetches them; agent downloads are blocked), `pnpm mk8:build` → gitignored `.mk8-out/`, served at `/mk8/` by `pnpm dev`; without it MK8 Mode shows "pack not installed". On Vercel, `scripts/fetchMk8Pack.mjs` (in `vercel.json`'s build command) copies the private repo `MattSharp05/kart-racer-mk8-assets` `out/` into `dist/mk8/` only when env `MK8_ASSETS_TOKEN` and `MK8_PASSWORD` are set, and Routing Middleware (`middleware.ts` → `gateMk8` in `api/mk8-login.ts`) answers 401 on every `/mk8/*` file (fonts excepted) without the `mk8_session` cookie from `POST /api/mk8-login` (optional `MK8_COOKIE_SECRET`). `public/mk8/` holds only shippable non-Nintendo files (the OFL font). Tests use synthetic fixtures; real-asset checks are deferred on tickets
- `src/scenarios/` scenario registry · `dev.html` + `src/dev/` = `/dev` index · `/dev/track-editor.html?course=<id>` (MK-100, `src/dev/trackEditor/`, guide `docs/mk8-track-editor.md`): authors an MK8 course's `route.ts`/`materials.ts` on its collision mesh; `src/sim/routeValidation.ts` checks routes; `pnpm dev` adds `POST /__track-editor/save`
- `src/content/` (v2, ADR 0007) — tracks, racers and items, one folder each. **To add one:** create `src/content/<tracks|racers|items>/<id>/` (folder name = id) with `sim.ts` (pure data/logic, sim lint rules; default-exports a `TrackContent`/`RacerContent`/`ItemContent`) and, for racers and items, `render.ts` (may import three; default-exports a `RacerView`/`ItemView`: model, colours, icon, sound, renderer), then add one line to that kind's list in `index.ts` (and `render.ts`); copy an existing folder as the template. No other shared file changes; ids are plain strings checked at lookup, and `registries.test.ts` fails if a folder isn't listed. **Track looks and hazards (MK-49):** a track's `theme` (sky, fog, light, palette, scenery set, night) and its `def.hazards[]` (`mover` · `rotator` · `periodic` · `zoneEffect`, poses a pure function of tick, kinds in `src/sim/hazards/`, views in `src/render/hazards/`) and surface zones (`ice` · `sand` · `conveyor`, effects in `src/sim/surfaces.ts`); `tracks/hazard-test/` is the worked example. A track folder may also have `scenarios.ts` (default-exports `Scenario[]`; one line in `tracks/scenarios.ts`), a `render.ts` (default-exports a `TrackView` whose `scenery()` replaces the theme's scenery set; one line in `tracks/render.ts`), and a zone hazard can take `warning` (HUD text 3 s before it starts) and `dust` (MK-58); `tracks/dune-canyon/` is the full example. MK-59 added a `mover` with an open path (`activeFraction`: runs now and then, gone in between) drawn as a rolling ball (`rolling`: shadow + rumble), and `TrackView.update(scenery, ticks, camera)` for moving scenery (falling snow); `tracks/frostpeak-pass/` uses both. MK-60 added `vehicle` on a `mover` (a car or truck with headlights), kart headlights on `night` tracks (`render/headlights.ts`) and AI steering round predicted movers (`sim/ai/hazards.ts`); `tracks/neon-harbour/` uses them. MK-61 added a `sway` hazard (a straight deck leaning on a timer that pushes karts sideways; its view draws the deck and, via `HazardView.hidesRoad`, replaces the road under it), `routes` (another way round part of a lap over a `shortcuts` floor: lap progress follows it, `sim/routes.ts`, and AI takes it on a seeded share of laps, `sim/ai/routes.ts`), `respawnPoints` (falls in a stretch put you back at its start) and `surface` on a shortcut (`road`: a paved lower path); `tracks/canopy-rush/` uses them. MK-62 added `piston` on a `periodic` crusher (drawn as a steam piston with a shadow, steam and a lamp that flashes `tuning.hazards.crusherWarningSeconds` before it drops, from the kind's `secondsUntilOn`) and AI crusher timing (`sim/ai/hazards.ts` `crusherSpeedLimit`: the AI slows to arrive as the next crusher opens); `tracks/cog-works/` uses them, plus conveyor belts (`conveyor` zones, one lane each way). MK-61 QA round 2 added `animal` on a `mover` (a boar, tapir, tapir calf or deer, `render/hazards/animal.ts`, 2 draws each) and AI dodging of movers on a route (`sim/ai/hazards.ts` `routeDodgeOffset`); `tracks/canopy-rush/` uses them for animals crossing its trail. Items build on the item framework (MK-52): `uses`, kart `effects` (`sim/items/effects.ts`), general `entities` (`sim/items/entities.ts`: straight/homing/returning/area + collision rules), `aiUse`, and in the view `sounds`, `entityModel`/`effectModel` (`renderer: ItemEntityRenderer`) and HUD `overlays` (a multi-use item's `iconFor(uses)` draws its uses left in the slot instead of a "×n" badge, MK-65: `items/turbo-trio/`); `items/test-kit/` is the worked example (`?scenario=item-framework-test`).
- `src/net/` (v2) transport (WebRTC · loopback · BroadcastChannel), binary protocol, rooms, host/client netcode · `supabase/migrations/` SQL schema
- `api/turn.ts` (MK-75, ADR 0008) — a Vercel Function: `GET /api/turn` returns short-lived Cloudflare TURN `iceServers` (env `CLOUDFLARE_TURN_KEY_ID` / `CLOUDFLARE_TURN_API_TOKEN`, Production only; none → 503). Self-contained (no `src/` imports); tests in `tests/api/` (run by `pnpm test`). The client side is `src/net/iceConfig.ts`: one fetch per WebRTC race, 3 s timeout, public STUN fallback
- `tests/e2e/` Playwright specs · `docs/` TDD, ADRs, CREDITS

## Conventions

- `src/sim/**` must not import `three`, DOM, input/render/ui/audio, nor use `Math.random`/`Date` (lint-enforced). Use `sim/rng.ts`.
- No magic numbers in logic — tunables go in `sim/tuning.ts` or data files.
- Units: metres, seconds, radians; +Y up; heading 0 faces −Z.
- Render/UI/audio only read `SimState` and `SimEvent`s; they never mutate sim state.
- `src/net/**` may import `sim/` types but never `render/`/`ui/`. Online races: the host is authoritative (ADR 0005); clients never decide hits, pickups or finishes.
- Screens live in `src/ui/screens/` with their own CSS; content (tracks, racers, items) registers itself (ADR 0007) — don't add cases to shared switches.
- New dependency or architectural change → `/block-ticket` and record an ADR.

## Testing

- Scenario rule: every testable state reachable via `/?scenario=<name>[&seed=][&paused=1]`, listed at `/dev` (`/dev.html` locally). Add scenarios in `src/scenarios/<group>.ts` and register them in `src/scenarios/index.ts`.
- Handling feel: `?tune=1` opens a live tuning panel (lil-gui, lazy-loaded) editing `src/sim/tuning.ts` values; "Copy values as JSON" to report numbers.
- E2E helpers in `tests/e2e/helpers.ts`: `loadScenario`, `pause`, `setInput`, `step`, `getState`. First run: `pnpm exec playwright install chromium webkit`.
- E2E: load a scenario, `__game.pause()`, `__game.setInput(...)`, `__game.step(n)`, assert on `__game.getState()` — never sleep/wait on real time for gameplay.
- Online (MK-46): `/?scenario=online-race-2p&net=local&role=host|client&room=<id>[&netsim=<rtt>,<jitter>,<loss%>][&laps=n]` races tabs of one browser over BroadcastChannel (no server). E2E: `openRoom(context, n)` (the test's `context` fixture, so a room never outlives its test) + `stepAll(pages, ticks)` from `tests/e2e/online.ts`, `__game.net()` for role/kart/RTT/snapshot tick; online specs (`tests/e2e/online*.spec.ts`) run only in the `desktop-chrome-online` / `desktop-webkit-online` projects, one test at a time, each its own CI job (MK-80). Lobby races over real WebRTC without Supabase (MK-73): `/?scenario=online-lobby&net=local&links=webrtc&role=host|client&room=<code>` (`links=blocked` drops the race's signaling, so it never connects: the "Connecting to …" state and the 20 s "Couldn't connect to …" fallback; `tests/e2e/onlineConnect.spec.ts`). `&netdebug=1` shows the net debug overlay (RTT, loss, re-sim, corrections, and each WebRTC link's path, `link P2P` or `link relay`, MK-75); `&relay=force` makes WebRTC races connect only through the TURN relay (production only: previews and local have no TURN key, so it is ignored there and the overlay shows `link P2P`); client smoothing / remote-kart mode live in `tuning.net` (`?tune=1` → Online); `&remote=interpolate` (MK-74) makes a client predict only its own kart and draw the others from the host's snapshots (`predict` is the default; `pnpm test:soak` takes `REMOTE=interpolate` and `TRACKS=`).
- Leaderboard (MK-56): CI builds have no Supabase settings, so e2e/visual tests use a stand-in backend: `&lb=mock` (made-up boards, your row at #37; races from scenario links count against it) or `&lb=offline`. The `leaderboard*` scenarios switch the mock on themselves (`leaderboard`, `-empty`, `-offline`, `-loading`, `-submit`).
- MK8 Mode (MK-97, ADR 0009): the title's MK8 Mode button imports `src/mk8/index.ts` (its own chunk) and `src/mk8/loader.ts` loads the pack from `/mk8/` (`pnpm dev` serves `.mk8-out/`; the site gates it, MK-135); no pack → the "MK8 pack not installed" screen, a 401 → the password box. `__game.whenReady()` resolves when pending pack loads finish (`loadScenario` awaits it). E2E serves the synthetic `tests/e2e/fixtures/mk8-pack/` with `servePack(page, { failOnce, hold, password })` from `tests/e2e/mk8.ts` (`password` runs the real gate + login handlers from `api/`). Scenarios: `mk8-entry`, `mk8-loading`, `mk8-not-installed`, `mk8-password`, `mk8-mode`.
- Every sim change gets Vitest unit tests; keep the determinism test passing.
- Playwright projects: desktop-chrome, desktop-chrome-online, desktop-webkit, desktop-webkit-online, iphone-landscape, ipad (the Pixel project was dropped in MK-89: software 3D at its resolution took 16 min per run, and it duplicated desktop-chrome's engine and iPhone's phone layout). Visual baselines are generated in CI (Docker), not locally.
- **CI has two levels (MK-89).** PRs run a fast gate, every job ≤ 5 min, all in parallel: lint/types/build, unit + sim perf, and desktop-chrome e2e split over 4 runners with `--grep-invert @full`. iPhone e2e + visual run only when UI/input/render/CSS change; the online e2e job + netsoak only when `src/net/` or online screens change; CI/config/dependency changes run everything. **Pushes to main run the full suite** (every device, `@full`, netsoak, visual). Tag a test `{ tag: '@full' }` if it takes more than ~30 s (full races, all-tracks sweeps): it then runs on main only. Main-only today: the 3-lap races, perf on all tracks, the every-scenario sweep (the unit `registry.test.ts` still builds every scenario on PRs), "choosing … starts a race" beyond the first 2 racers, and the online full races (onlineFlow, onlinePrediction's finish, onlineDrops' rejoin). A red main is fixed before anything else merges.
